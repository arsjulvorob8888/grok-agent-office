# Личные токены агентов

Короткая спека. Общий `AGENT_TOKEN` в заголовке `x-agent-token` заменяется личным токеном агента. Сам токен нигде не хранится и не пишется в лог: в базе только его хеш.

## Хранение

Миграция 9, таблица `agent_tokens`:

| Колонка | Смысл |
|---|---|
| `id` | Случайный id строки, не секрет |
| `agent_id` | Id агента с карты |
| `token_hash` | SHA-256 токена, hex. Самого токена в строке нет |
| `created_at` | Когда выпущен |
| `revoked_at` | Когда отозван. Пусто — токен ещё действует |

Повторный выпуск для того же агента ставит `revoked_at` старым строкам и добавляет новую. В `GET /api/state` нет ни токена, ни хеша, ни этой таблицы.

## Проверка `x-agent-token`

Сравнение за постоянное время: хеш предъявленного токена сверяется с `token_hash` через `crypto.timingSafeEqual`, общий секрет — тем же приёмом, что и раньше.

Агент запроса берётся из тела (`agentId`, для статуса ещё `agent`, для пункта «Нужно от вас» — `fromAgentId`) или из пути (`/api/agents/:id/...`). Для `POST /api/orders/:id` это исполнитель приказа. Для `POST /api/needs/:id/confirm` — автор пункта.

| Ситуация | Ответ |
|---|---|
| Токен найден и агент тот же | дальше обычная проверка тела |
| Токен найден, но агент в запросе другой | `403` «Токен другого агента» |
| Такого токена нет | `401` «Неверный токен агента» |
| Токен отозван | `401` «Неверный токен агента» |
| Нет заголовка и нет ни общего секрета, ни живых личных токенов | `503` |

## Переходный режим

Пока у агента нет живого личного токена, общий `AGENT_TOKEN` для него по-прежнему принимается. Как только для этого агента выпущен личный токен, общий для него больше не принимается: `401` «Для этого агента нужен личный токен». На агентов без своего токена общий секрет продолжает действовать. Отзыв последнего личного токена снова открывает агенту общий секрет.

`POST /api/agent-status` по-прежнему смотрит только `AGENT_STATUS_TOKEN`. Ручки без агента в запросе — снимок лимита и здоровье доставки — по-прежнему принимают общий `AGENT_TOKEN`. Синхронизация с «Порядком» этим не затрагивается.

## Админка

Пароль владельца тот же, что и раньше: `APP_PASSWORD`, заголовок `x-app-password`, в браузере он лежит только в `localStorage` после входа. Без этого пароля выпуск и отзыв отвечают `401`.

`POST /api/agent-tokens` с телом `{ "agentId" }` выпускает токен одному агенту. Без `agentId` — всем неархивным агентам ростера. Ответ `201`:

```json
{
  "ok": true,
  "warning": "Токен показывается один раз. Повторно его не увидеть. Старые токены этого агента отозваны.",
  "tokens": [{ "agentId": "dev", "name": "Программирование", "token": "…" }]
}
```

Повторного чтения нет. `POST /api/agent-tokens/:agentId/revoke` ставит `revoked_at` живым строкам этого агента.

В окне агента после входа владельца есть блок «Токены агентов»: кнопка «Выпустить токены» (всему ростеру или только выбранному), показ один раз с кнопкой «Копировать» и тем же предупреждением, кнопка «Отозвать» для выбранного агента.
