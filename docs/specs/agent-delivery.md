# Доставка: вебхук агента и общий вебхук Путина

Короткая спека. В окне агента сотрудник задаёт, куда уходит событие из очереди `outbox`. Секрет хранится в Postgres в зашифрованном виде. Статусы на карточке не новые: их по-прежнему пишет `deliveryLabel` («В очереди, доставка не подключена», «Отправлена», «Ошибка доставки» и код).

Пароль персонала — тот же пароль штаба, что у «Дать задачу» и `POST /api/outbox/retry`: заголовок `x-app-password`, в браузере `localStorage.appPassword`.

## Что видит сотрудник

Блок монтирует `public/js/delivery-panel.js` в `#panel`, сразу под строкой статуса. Скрипт отдельный от `app.js`, чтобы не переписывать панель.

Без сохранённого пароля блока с полями нет. Видна только подпись «Доставка» и кнопка «Ввести пароль». Она открывает тот же пропуск, что и остальные защищённые действия. URL и хвост ключа в этот момент в HTML не попадают.

С паролем у каждого агента блок «Доставка»:

- поле «URL вебхука»;
- поле «Ключ», `input type="password"`. После загрузки и после сохранения значение пустое. Рядом текст «Ключ задан» и последние 4 символа, если ключ есть. Если ключа нет — «Ключ не задан»;
- кнопка «Сохранить»;
- кнопка «Проверить»;
- строка, куда сейчас пойдут события: вебхук агента, общий вебхук Путина, запасной адрес из окружения или «Доставка не настроена». Сам запасной URL из окружения на страницу не выводится.

Пустое поле ключа при сохранении оставляет прежний ключ. Галка «Сбросить ключ» стирает его. Пустая строка URL удаляет запись этого адреса, и события идут на следующую ступень.

У Путина (`grok`) два блока. Сверху «Общий вебхук» — запасной адрес для всех, у кого своего URL нет. Под ним обычная «Доставка» самого Путина. Общий вебхук в интерфейсе больше ни у кого не редактируется.

«Проверить» шлёт на выбранный URL одно событие и показывает «Ответ» и HTTP-код либо «Таймаут» или «Нет связи». В очередь `outbox` эта проверка не встаёт.

## Куда уходит событие очереди

Для `agentId` элемента outbox, по порядку:

1. Запись этого агента, если URL непустой.
2. Иначе запись общего вебхука Путина (id `putin`), если URL непустой.
3. Иначе `KREMLIN_WEBHOOK_URL` и `KREMLIN_WEBHOOK_KEY`, как раньше.
4. Иначе никуда: элемент остаётся `queued`, `forwardStatus` пустой, подпись «В очереди, доставка не подключена».

`POST /api/outbox/retry` с паролем штаба делает один проход. Если нет ни одной ступени, ответ `409` и прежний текст «KREMLIN_WEBHOOK_URL не задан». Уже `delivered` повторно не отправляются.

Ключ в заголовках тот же, что у рутины Кремля: `Authorization` и `x-webhook-key` через `parseKremlinKey`. Дополнительное имя из `KREMLIN_WEBHOOK_HEADER` по-прежнему только для запасного варианта из окружения. JSON в переменные окружения не кладётся.

Если запись есть, но `WEBHOOK_SECRETS_KEY` не задан или не подходит, на следующую ступень не перескакиваем: попытка считается ошибкой, в логе `error=decrypt_error`, подпись «Ошибка доставки 0».

Успешный ответ по-прежнему даёт `forwardStatus` 2xx и подпись «Отправлена». Чужой код — «Ошибка доставки» и этот код.

## API

Все четыре маршрута требуют `x-app-password`. Без пароля или с неверным — `401` «Неверный пароль доступа». Неизвестный агент — `404` «Неизвестный агент». Id `putin` на маршруте агента не принимается: общий вебхук только на своём пути.

| Метод | Путь |
|---|---|
| `GET`, `PUT` | `/api/agents/:id/delivery` |
| `POST` | `/api/agents/:id/delivery/test` |
| `GET`, `PUT` | `/api/delivery/putin` |
| `POST` | `/api/delivery/putin/test` |

Ответ чтения и сохранения:

```json
{ "agentId": "army", "url": "https://example.test/hook", "keySet": true, "keyTail": "wxyz", "route": "agent" }
```

У общего вебхука вместо `agentId` поле `id` со значением `putin`. `route` — `agent`, `putin`, `env` или `none`. Поля `key` нет. В `GET /api/state` этих записей нет.

`PUT` принимает JSON `{ "url", "key", "clearKey" }`. `url` — строка, обязательна. Пустая строка удаляет запись и для удаления ключ шифрования не нужен: открытый текст не пишется. Непустой URL — только `http` или `https`, без логина и пароля в адресе, без перевода строки, не длиннее 2000 символов. `key` — строка до 500 символов, без перевода строки. Пустая строка или отсутствие `key` оставляет старый ключ. `clearKey: true` записывает пустой ключ.

`POST .../test` принимает необязательные `url` и `key` — то, что сейчас в полях, ещё не сохранённое. Если ключ в теле пустой, а URL совпадает с сохранённым, уходит сохранённый ключ. На другой URL сохранённый ключ не подставляется. Тело вебхука:

```json
{ "type": "test", "agentId": "army", "text": "Проверка доставки", "at": "2026-11-17T12:00:00.000Z", "atMsk": "17.11 15:00 МСК", "appUrl": "https://example.test" }
```

У общего вебхука `agentId` равен `putin`. Ответ проверки: `{ "ok", "status" }`, а при обрыве ещё `error`: `timeout` или `network_error` и `status: 0`. Тело ответа вебхука наружу не копируется. Своего URL нет — `409` «URL вебхука не задан».

Без `WEBHOOK_SECRETS_KEY` или если это не 32 байта base64, сохранение и чтение шифротекста отвечают `503`. Текст отсутствия ключа: «Не задан WEBHOOK_SECRETS_KEY, вебхук не сохранён». Текст неверного ключа: «Ключ WEBHOOK_SECRETS_KEY не подходит, вебхук не прочитан». Запись при этом не меняется и открытым текстом не пишется.

## Хранение

Таблица `webhook_targets`, миграция 6 в `lib/store.js`. Одна строка — один адрес: id агента или `putin`. Колонки `iv`, `tag`, `ciphertext` — base64. Внутри AES-256-GCM одна связка `{ "url", "key" }`. IV — 12 случайных байт на каждую запись, тег — 16 байт. Дополнительные данные шифра — id записи, чтобы строку нельзя было переставить другому агенту.

Ключ шифра — `WEBHOOK_SECRETS_KEY`, 32 байта в base64. Он уже задан на Render (`sync: false` в `render.yaml`). В репозитории значения нет.

Без `DATABASE_URL` шифротекст живёт только в памяти процесса, как и остальные данные, и после рестарта пропадает. Открытый URL и ключ в память хранилища и в строку Postgres не кладутся.

## Логи

Попытка очереди — прежняя строка `webhook attempt` без URL, ключа, заголовков и текста. Проверка — одна строка `webhook test target=<id> http=<код>|error=<вид> ms=<мс>`. В ней нет URL, ключа и текста события.

## Сценарии для тестировщика

1. Открыть агента без пароля в браузере. В окне есть «Доставка» и «Ввести пароль». Полей URL и ключа нет. Если адрес уже сохраняли, его нет в HTML страницы.
2. Ввести пароль штаба. Появляются «URL вебхука» и «Ключ». У ключа `type=password`. Сохранить `https://` адрес локальной рутины и ключ длиннее 4 символов. Поле ключа снова пустое. Видны «Ключ задан» и последние 4 символа. Полного ключа нет ни в ответе API, ни в HTML, ни в логе сервера.
3. «Проверить» на этой рутине. Рутина получает JSON с `type` равным `test` и заголовок с ключом. В окне «Ответ 200». В `outbox` новой записи от этой кнопки нет. Остановить рутину и нажать снова: виден код ошибки или «Нет связи», без текста ключа.
4. Пустой ключ и тот же URL при сохранении не сбрасывают ключ: проверка снова приходит с прежним заголовком. Галка «Сбросить ключ» — следующая проверка уже без ключа. Пустой URL снимает адрес агента.
5. Задача агенту с его URL уходит на этот URL, а не на `KREMLIN_WEBHOOK_URL`. Снять адрес агента, задать общий вебхук Путина — следующая задача того же агента уходит Путину. Снять и его — задача уходит на `KREMLIN_WEBHOOK_URL`. Снять все три — задача остаётся в очереди, подпись «В очереди, доставка не подключена». Успех — «Отправлена». Ответ 500 — «Ошибка доставки 500».
6. У окна Путина два блока: «Общий вебхук» и «Доставка». У другого агента общего блока нет.
7. Убрать `WEBHOOK_SECRETS_KEY` и сохранить непустой URL. Ответ 503 с текстом про ключ. В хранилище новая строка не появляется, в теле ошибки нет URL и ключа из формы. Вернуть неверный ключ (другая строка base64 на 32 байта) при уже сохранённой записи: чтение 503, в ответе нет расшифрованного URL. Постановка задачи не уходит на запасной URL из окружения, подпись «Ошибка доставки 0».
8. С `DATABASE_URL` сохранить адрес, остановить процесс, поднять снова с тем же `WEBHOOK_SECRETS_KEY` и `STORE_SCHEMA`. `GET` показывает тот же URL и те же 4 символа, полного ключа нет. В таблице `webhook_targets` в `iv`, `tag` и `ciphertext` нет открытого URL и ключа. Без `DATABASE_URL` после рестарта записи нет. В логе нет ключа и URL.
