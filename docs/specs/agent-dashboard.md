# Дашборд агента

Окно агента раскрывается на весь экран: обзор, задачи, аналитика и переписка. Карта, нижняя лента аватарок и идентификатор `owner` не меняются. Новые файлы: `public/js/agent-dashboard.js`, `public/css/agent-dashboard.css`, `lib/agent-dashboard.js`. В `server.js` только два маршрута, в `index.html` — подключение стилей, пустой контейнер и скрипт.

## Ссылка и история

- В шапке панели агента кнопка «Развернуть» (`button`, доступна с клавиатуры). Она видна только у открытой панели.
- Адрес становится `#agent=<id>&view=dashboard&tab=<вкладка>`. Вкладки: `overview`, `tasks`, `analytics`, `chat`. Чужой `tab` открывает «Обзор».
- Кнопка «Развернуть» добавляет запись в историю. «Назад» в браузере закрывает дашборд и возвращает карту. Прямая ссылка открывает дашборд без клика по карте.
- «Свернуть» и Esc закрывают дашборд. Если его открыли кнопкой, это тот же шаг, что «Назад». Если открыли по ссылке, адрес теряет `view=dashboard`, страница остаётся картой.
- Смена вкладки не плодит шаги истории: «Назад» закрывает дашборд, а не предыдущую вкладку.
- Esc в поле ввода тоже сворачивает дашборд и не закрывает панель агента и помещение.

## Раскладка

Полноэкранный диалог `#agentDash`: `role="dialog"`, `aria-modal="true"`, заголовок с именем агента. Вкладки — `role="tablist"` / `role="tab"` / `role="tabpanel"`, у выбранной `aria-selected="true"`. Фокус при открытии попадает на «Свернуть». Фон под диалогом не попадает в Tab, пока дашборд открыт. После закрытия фокус возвращается на «Развернуть», если кнопка ещё на экране.

Разворот — opacity и сдвиг за 250 мс. При `prefers-reduced-motion: reduce` переходов нет.

На ширине до 700px вкладки стоят снизу, колонки канбана друг под другом, горизонтальной прокрутки страницы нет. На широком экране вкладки под шапкой, канбан в три колонки.

## Обзор

Данные только из `GET /api/agents/:id/dashboard`.

- Статус агента — те же слова, что на карте: активность (`working` / `waiting` / `resting`) и поле `now`. Если у агента есть объект `live` со статусом `working` или `idle`, дополнительно строка живого хода и поле `doing`. Нет `live` — строки живого хода нет, статус карты остаётся.
- Текущая задача — та же, что облачко на карте (`currentTask`). Нет задачи — «Сейчас нет задачи».
- Карточки: задач всего, выполнено, в работе. Выполнено — `orderStatus: done` или старый статус «выполнена», но не `failed`. В работе — `accepted` и `in_progress`.
- Уровень и опыт считаются как в панели: 100 за выполненную задачу (`completed`), 10 за каждую задачу, где агент исполнитель, порог уровня 150 и дальше +75. Цифры совпадают с полоской опыта в панели.
- Последние активности: реальные отметки истории приказов и реплики с временем. Строки `done` без времени показываются без выдуманной даты. Пустой список — «Пока нет активности».

## Проекты и задачи

Задачи агента — приказы, где он исполнитель (`agentId` или `agent`). Колонки:

| Колонка | Статусы |
|---|---|
| Новые | `sent` и прочие незакрытые, кроме принятых и тех, что в работе |
| В работе | `accepted`, `in_progress` |
| Готово | `done`, `failed` и старая «выполнена» |

`failed` лежит в «Готово» с подписью «Не выполнен», из списка не пропадает.

Есть переключатель «Список» / «Канбан», поиск по тексту и фильтр колонки. Пустой результат поиска — «Ничего не найдено», не пустой канбан без пояснения.

«Создать задачу» вызывает существующий `POST /api/task` с паролем штаба (`x-app-password`, тот же `APP_PASSWORD`). `fromAgentId` остаётся `owner`, идентификатор не переписывается. Архивному и свободному направлению кнопка создания не предлагается: сервер и так отвечает 409 и 400.

Смена статуса — `POST /api/agents/:id/orders/:orderId` с тем же паролем. Переходы те же, что у `POST /api/orders/:id`: из `sent` можно в `accepted` или `failed`, дальше по цепочке, закрытый приказ назад не открывается. Кнопка «В работу» с новой карточки ставит `accepted` (колонка «В работе»). «Готово» требует непустой итог. Без пароля и с чужим паролем — 401, приказ не меняется. Чужой приказ в адресе этого агента — 404.

## Аналитика

Графики — свой SVG, без новой библиотеки. Числа приходят с API.

- Задачи по дням за 14 дней, сутки по Москве (UTC+3). День без задач — 0. Если задач нет совсем, графика нет, текст «Пока нет задач».
- Распределение по `orderStatus`: `sent`, `accepted`, `in_progress`, `done`, `failed`. Нет задач — блока с нулями нет.
- Среднее время выполнения: от `createdAt` до отметки `done` в истории. Нет ни одной такой пары — «Нет завершённых задач», не ноль.
- Доля доставленных считается по полю `deliveryLabel`, которое задача получает в `publicTask` (`deliveryLabelFor`): подпись есть только пока `orderStatus` равен `sent`. Числитель — реплики владельца с подписью «Отправлена», знаменатель — реплики владельца, у которых подпись есть. Нет таких реплик — «Нет сообщений с доставкой», не «0%». Дашборд очередь outbox не пишет.

Имя отправителя — `senderName` из `public/js/sender-label.js` («Путин» для `owner`). Старый текст «Приказ: Владелец →» на экране читается через `displayOrderSender`. Идентификатор `owner` не меняется.

## Переписка

История — сообщения этого агента, включая системные строки приказов. У реплики владельца, связанной с задачей, виден `deliveryLabel`. Enter отправляет, Shift+Enter переносит строку. Отправка — снова `POST /api/task`: в этой модели приказ и есть реплика владельца. Шаблоны («Доложи статус», «Что в работе», «Пришли итог») только подставляют текст в поле, сами не отправляют.

Нет пароля — поле остаётся, отправка показывает «Нужен пароль штаба» и не стирает текст.

## API

`GET /api/agents/:id/dashboard` без пароля, как `GET /api/state`. Неизвестный id — 404 «Неизвестный агент». В ответе нет пароля, токена, строки подключения и `forwardError`.

Защищённое действие — смена статуса приказа. Создание задачи остаётся на `POST /api/task`.

Новых колонок в Postgres нет: статус, история, `forward_status` и время уже лежат в `orders` и `messages`.

## Вне скоупа

Живой ход с отдельным токеном, очередь outbox, подпись «Путин →» вместо «Владелец», перетаскивание карточек мышью, вложения в дашборде, отдельная сущность «проект».
