# Postgres-хранилище офиса

Короткая спека для `lib/store.js`. `GET /api/state` читает память. База только загружается при старте и принимает запись изменений. Без `DATABASE_URL` или если Postgres недоступен при старте процесс не падает: одна строка в лог, дальше память и `UPLOAD_DIR`. Строку подключения в лог не пишем.

## Что храним

| Таблица | Содержимое |
|---|---|
| `schema_version` | Номера применённых миграций. Схема создаётся при старте, отдельный SQL не нужен. |
| `orders` | Приказы и задачи: исполнитель, отправитель, родитель, статус, история, вложения-ссылки, прочие поля в `extra`. |
| `needs` | Пункты «Нужно от вас»: текст, место, срочность, `closedAt`. В `extra`: `kind`, `docUrl`, `participants`, `answerMode`, `answers` (`text`, `at`, `by`), `answer`, `answeredAt`, `updatedAt`, `closedBy`, частичный ответ. |
| `messages` | Переписка, включая системные строки. |
| `files` | Байты вложений в `bytea`. Лимиты прежние: 10 МБ и 5 файлов. `GET /api/files/:id` отдаёт тот же `Content-Type` после рестарта и нового деплоя. |
| `agent_state` | Архив и payload. У посевного агента из кода берётся карточка (имя, место, `archived`), а из базы — `status`, `now`, `done`, `completed`, пульс, дашборд и `analysis`. `completed` и сохранённые задачи дают опыт после рестарта. Динамический агент из `POST /api/status` возвращается целиком. |
| `routines` | Рутины агентов. |
| `app_state` | Ключ `migrations`: флаги вроде `financeTextReopen`. Повторный старт не прогоняет уже выполненную миграцию. Ключ `grokUsage`: последний снимок лимита Grok и история за 7 дней. |
| `outbox` | Очередь вебхука Кремля: id, время, агент, задача, статус `queued`/`delivered`, попытки, последняя ошибка и полезная нагрузка. Миграция 5. |
| `webhook_targets` | Зашифрованные URL и ключ вебхука агента и общий вебхук Путина (`id` `putin`). В строке только `iv`, `tag`, `ciphertext`. Миграция 6. |
| `decisions` | Журнал ответов владельца: момент, id пункта, вопрос, ответ, автор вопроса, источник `сайт`. Миграция 7. Ответы `kind=test` и `kind=secret` сюда не пишутся. |

Посев пунктов — только в пустую таблицу `needs`. `need-render-api` и `need-academy` в непустую базу не возвращаются. `need-test-qa` и `need-test-question` вне production снова открываются при деплое и через 5 минут, даже если уже лежат в базе. При `NODE_ENV=production` закрытый тестовый пункт остаётся закрытым, пока нет `TEST_NEEDS_AUTOREOPEN=1`.

`financeTextReopen` один раз открывает закрытый `need-finance` без текстового ответа. После записи флага повторный рестарт пункт сам не открывает. Открытый пункт с `answer` или непустым `answers` при старте закрывается с `closedBy: owner-answer` и дописывается в `decisions`. Повторный старт `closedAt` не двигает и строку журнала не копирует. `kind: test` и текст `kind: secret` в журнал не попадают.

## Подключение

`DATABASE_URL` — pooled-строка Neon к базе `kremlin`: хост с `-pooler`, `sslmode=require`. Пул `pg` не больше 3 соединений, таймаут подключения 10 секунд, простой 10 секунд. После scale-to-zero старое соединение не держим: следующий запрос открывает новое. Секретов в репозитории нет. В `render.yaml` у вебхука ключи `KREMLIN_WEBHOOK_URL` и `KREMLIN_WEBHOOK_KEY` (`sync: false`). `GROK_WEBHOOK_*` в Blueprint нет. `DATABASE_URL` тоже `sync: false`.

## Сценарии для тестировщика

1. Без `DATABASE_URL` создать задачу, остановить процесс, поднять снова. Задачи, переписки и файлов нет. Офис отвечает.
2. С базой записать пункт и частичный ответ, приказ, сообщение, файл и `completed` посевного агента (`status`, `now`, `done`). Поднять новый процесс на той же базе. Всё на месте, файл открывается с прежним типом.
3. Закрыть `need-finance` без текстового ответа при `financeTextReopen: false`. Новый процесс открывает пункт один раз и запоминает флаг. Ещё один рестарт пункт закрытым не открывает.
4. Недоступная база при старте: одна строка «Postgres недоступен», строка подключения и пароль в лог не попадают.
