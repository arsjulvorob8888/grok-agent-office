# Очередь доставки вебхука Кремля

Короткая спека. Задача и сообщение владельца с сайта не пропадают, если `KREMLIN_WEBHOOK_URL` пуст или рутина не ответила. Они лежат в `state.outbox` и, когда задан `DATABASE_URL`, пишутся в Postgres таблицей `outbox` (`lib/store.js`, миграция 5). Без базы очередь живёт только в памяти процесса и после рестарта пуста — как и остальные данные.

## Запись

У элемента есть `id` (`ob-N`), время `at`, `agentId`, `taskId`, полезная нагрузка вебхука и `status`: `queued` или `delivered`. В полезной нагрузке тот же JSON, что уходит на рутину, плюс `id` элемента. Тот же `id` уходит в заголовке `x-outbox-id`. Ключ вебхука в запись и в лог не попадает.

Пока элемент `queued` и приказ ещё `sent`, агент на карте не становится `working` из‑за этой задачи (`lib/activity.js` такую задачу текущей не считает). В окне агента и на карточке вместо «В работе»:

- URL пуст или у записи пустой `forwardStatus`: «В очереди, доставка не подключена». В API это `deliveryLabel`, `lastError` пустой. Так же для старых строк в Postgres, у которых нет outbox.
- Ответ не 2xx, обрыв или таймаут: «Ошибка доставки» и код (`Ошибка доставки 502`, обрыв — `Ошибка доставки 0`). Статус outbox остаётся `queued`, в `lastError` короткое `HTTP <код>`, `timeout` или `network_error`.

Успех ставит `delivered`, задаче — «отправлена Путину», агенту — обычное «В работе».

## Отправка

Адрес берётся так: вебхук агента, иначе общий вебхук Путина, иначе `KREMLIN_WEBHOOK_URL`. Как задать первые два — в `docs/specs/agent-delivery.md`.

Один проход, по времени, строго по очереди, таймаут запроса 10 секунд. Уже `delivered` повторно не отправляются.

1. Сразу при постановке задачи, если URL задан.
2. Один раз при старте, после загрузки хранилища, если URL задан и есть `queued`.
3. `POST /api/outbox/retry` с паролем штаба (`x-app-password`). Без пароля — 401. Бесконечных повторов нет.

Каждая попытка — одна строка лога: id, агент, номер попытки, HTTP-код или `timeout`/`network_error`, время в мс. В строке нет URL, ключа, заголовков и текста сообщения.

## Здоровье доставки

`GET /api/health/delivery`. Без служебной авторизации — 401. Подходит то же, что у агентов и штаба: `Authorization: Bearer <AGENT_TOKEN>`, заголовок `x-agent-token` или пароль владельца `x-app-password`.

```json
{
  "webhookUrlSet": true,
  "webhookKeySet": false,
  "agentWebhooks": 0,
  "putinWebhookSet": false,
  "lastDelivery": { "at": "2026-11-17T12:00:00.000Z", "status": 200, "outboxId": "ob-1" },
  "queued": 0,
  "delivered": 1
}
```

`lastDelivery` — `null`, пока попыток не было. При сетевой ошибке вместо `status` поле `error`. `agentWebhooks` — сколько агентов хранят свой вебхук. `putinWebhookSet` — задан ли общий вебхук Путина. Адресов и ключей в ответе нет.

## Сценарии

1. Пустой `KREMLIN_WEBHOOK_URL`: задача в `state.outbox` со статусом `queued`, агент не `working`, в API и в окне текст «В очереди, доставка не подключена».
2. URL задан, в очереди есть элементы: при старте они уходят по порядку, успешные становятся `delivered`, уже доставленные не дублируются.
3. Вебхук ответил не 2xx или сеть оборвалась: элемент остаётся `queued` с `lastError`, на карточке «Ошибка доставки» и код. В логе есть строка попытки и нет URL и ключа.
4. С `DATABASE_URL` очередь переживает новый процесс. Без базы — нет.
5. `GET /api/health/delivery` без авторизации — 401. С токеном или паролем штаба — форма выше, без секретов.
6. Подпись доставки одна и та же в «Процессы сейчас», в ленте и в истории приказа, в том числе у старых записей из базы, где нет строки outbox, а есть только `forwardStatus`. `2xx` — «Отправлена». `forwardStatus` пустой — «В очереди, доставка не подключена». Иной код — «Ошибка доставки» и сам код (`Ошибка доставки 502`). Принятый и уже идущий приказ по-прежнему «Принял» и «В работе». Отправитель с id `owner` на экране — «Путин →», идентификатор `owner` не меняется.
