# Ответ агента в Кремль

Агент пишет реплику в своё окно и в ленту и привязывает её к задаче. Токен тот же, что у `POST /api/status`: заголовок `x-agent-token`.

```bash
curl -sS -X POST "$PUBLIC_URL/api/messages" \
  -H "Content-Type: application/json" \
  -H "x-agent-token: $AGENT_TOKEN" \
  -d '{
    "agentId": "social",
    "role": "agent",
    "taskId": "t-12",
    "text": "Пост опубликован"
  }'
```

Тело JSON:

| Поле | Правило |
|---|---|
| `agentId` | id агента с карты, обязателен |
| `role` | `agent` для ответа исполнителя |
| `taskId` | id приказа. Обязателен, если у реплики нет своего `id` для дедупа ретранслятора. Неизвестный id — `400` «Неизвестная задача». Чужая задача — `400` «Задача другого агента» |
| `text` | строка, для `role: agent` не длиннее 4000 символов |

Успех — `201` и `{ "ok": true, "duplicate": false, "message": { "id", "agentId", "role", "text", "taskId", "source": "relay" } }`. Повтор того же `id` — `200` и `duplicate: true`, вторая строка не пишется.

Чужой или пустой токен — `401` «Неверный токен агента». Нет токена в окружении — `503`.

Частота: 30 реплик на агента за 60 секунд. Дальше `429`, заголовок `Retry-After: 60`, тело `{ "error": "Слишком часто" }`.

С `DATABASE_URL` реплика лежит в Postgres и переживает рестарт. В ленте текст экранируется: HTML из `text` не становится разметкой.
