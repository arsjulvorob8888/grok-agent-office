# Ответ агента в Кремль

Агент пишет реплику в своё окно и в ленту и привязывает её к задаче. Заголовок `x-agent-token` — личный токен этого `agentId`.

## Откуда у агента токен

Владелец выпускает токен сам и сам передаёт его агенту.

1. Открыть Кремль и нажать кнопку ключа «Пароль доступа» в шапке.
2. Ввести `APP_PASSWORD` и нажать «Войти». Пароль остаётся только в этом браузере.
3. Открыть агента. В панели блок «Токены агентов».
4. В списке оставить «Только выбранный агент» или выбрать «Все агенты ростера».
5. Нажать «Выпустить токены». Для всего ростера браузер спросит подтверждение: старые личные токены этих агентов перестанут работать.
6. Токен виден один раз. Рядом кнопка «Копировать» и предупреждение, что повторно его не увидеть. Скопировать и передать агенту лично.
7. «Отозвать» гасит личные токены выбранного агента.

В репозиторий токен не кладётся. Сервер не пишет его в лог. `GET /api/state` его не отдаёт. В Postgres, таблица `agent_tokens` (миграция 9), лежит только SHA-256 в `token_hash`, плюс `agent_id`, `created_at` и `revoked_at`. Повторного чтения токена нет.

Пока у агента нет живого личного токена, заголовок принимает общий `AGENT_TOKEN`. Как только личный токен выпущен, общий для этого агента больше не принимается (`401`, «Для этого агента нужен личный токен»). Агенты без своего токена по-прежнему ходят с общим. После отзыва последнего личного токена общий для этого агента снова годится.

Чужой `agentId` (в теле, в пути `/api/agents/:id/...` или как исполнитель `POST /api/orders/:id`) с чужим живым токеном — `403` «Токен другого агента». Неизвестный или отозванный токен — `401` «Неверный токен агента». Без пароля владельца выпуск и отзыв — `401`.

```bash
curl -sS -X POST "$PUBLIC_URL/api/messages" \
  -H "Content-Type: application/json" \
  -H "x-agent-token: $AGENT_TOKEN_SOCIAL" \
  -d '{
    "agentId": "social",
    "role": "agent",
    "taskId": "t-12",
    "text": "Пост опубликован"
  }'
```

`$AGENT_TOKEN_SOCIAL` — личный токен агента `social`, не общий `AGENT_TOKEN` и не секрет из репозитория.

Тело JSON:

| Поле | Правило |
|---|---|
| `agentId` | id агента с карты, обязателен. Должен совпасть с владельцем токена |
| `role` | `agent` для ответа исполнителя |
| `taskId` | id приказа. Обязателен, если у реплики нет своего `id` для дедупа ретранслятора. Неизвестный id — `400` «Неизвестная задача». Чужая задача — `400` «Задача другого агента» |
| `text` | строка, для `role: agent` не длиннее 4000 символов |

Успех — `201` и `{ "ok": true, "duplicate": false, "message": { "id", "agentId", "role", "text", "taskId", "source": "relay" } }`. Повтор того же `id` — `200` и `duplicate: true`, вторая строка не пишется.

Чужой или пустой токен — `401` «Неверный токен агента». Токен другого агента — `403`. Нет ни общего секрета, ни живых личных токенов — `503`.

Частота: 30 реплик на агента за 60 секунд. Дальше `429`, заголовок `Retry-After: 60`, тело `{ "error": "Слишком часто" }`.

С `DATABASE_URL` реплика лежит в Postgres и переживает рестарт. В ленте текст экранируется: HTML из `text` не становится разметкой.

## Живой статус: имя профиля → id

`POST /api/agent-status` принимает `Authorization: Bearer` с `AGENT_STATUS_TOKEN`. Имя сравнивается без регистра и лишних пробелов, точка `·` может стоять вплотную. Подробности — в `docs/specs/live-status-names.md`.

| Имя профиля | id на карте |
|---|---|
| Путин · Кремль | `grok` |
| Программирование · Кремль | `dev` |
| Здоровье и спорт · Кремль | `health` |
| Technology Blog · Кремль | `blog` |
| Трейдинг · Кремль | `trading` |
| Language Coach | `lang` |
| Темщик · Кремль | `temshik` |
| Тестировщик ПО · Кремль | `qa` |
| Советник · Кремль | `advisor` |
| Соцсети · Кремль | `social` |
| Business Adviser | `biz` |
| Военная служба · Кремль | `army` |
| DevOps · Кремль | `devops` |
| Рутины · Кремль | `routines` |
| Покер · Кремль | `poker` |
| Финансы · Кремль | `finance` |

Точный id `grok` и короткое имя `Путин` — это Путин. Голое `Grok` в другом регистре — `404`, это не Путин.

| Ситуация | Ответ |
|---|---|
| Имя узнано, агент не в архиве | `200` `{ "ok": true, "id": "..." }` |
| Имя узнано, архив, но есть `parentId` (зам: `trading` и `biz` у Финансов) | `200` `{ "ok": true, "id": "..." }`. На общей карте агента нет, ход виден в помещении начальника |
| Имя узнано, архив без `parentId` (`lang`) | `409` `{ "error": "агент в архиве на карте — статус не принят", "agentId": "lang" }` |
| Имя не узнано, в том числе `Grok` | `404` `{ "error": "Неизвестный агент" }` |
| Нет или чужой токен живого статуса | `401` |
| `AGENT_STATUS_TOKEN` не задан | `503` |
