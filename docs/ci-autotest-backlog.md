# Автотесты трёх ручных сценариев

Короткая заметка к проверкам, которые на проде смотрели вручную. Продуктовое поведение эти тесты не меняют.

## Принятый заказ

Спека `docs/specs/sender-label.md`, сценарий 3. Приказ с `fromAgentId: owner`, принятый с заметкой «Владелец ждёт», в `GET /api/state` и в `GET /api/agents/dev/dashboard` отдаёт системную строку «Принял заказ · Владелец ждёт». Рядом строка приказа на дашборде читается как «Приказ: Путин → Программирование». Идентификатор отправителя остаётся `owner`.

Тест: `test/sender-label.test.js`, «принятый заказ возвращает «Принял заказ · Владелец ждёт»».

## Postgres между процессами

Один процесс записывает приказ и принятие. После его остановки новый процесс с тем же `DATABASE_URL` и `STORE_SCHEMA` видит текст, `orderStatus: accepted`, заметку «Владелец ждёт» и строку «Принял заказ · Владелец ждёт». Строка подключения берётся из окружения CI: в `.github/workflows/ci.yml` уже есть сервис Postgres 17 и `DATABASE_URL` на локальную базу `office`. Секретов и продовой строки в тесте нет. Без `DATABASE_URL` проверка пропускается, как остальные тесты хранилища.

Тест: `test/store.test.js`, «запись одного процесса видна свежему процессу».

Рядом по-прежнему живут «созданная задача остаётся в /api/state после нового процесса» и «Postgres сохраняет приказ, пункт, сообщение и файл после перезапуска».

## financeTextReopen

Флаг `state.migrations.financeTextReopen`. Закрытый `need-finance` с ответом «Да» и без текстового ответа открывается один раз: `closedAt` пустой, `answerMode` — `text`, у ответа пометка «до текстового поля». `need-social` остаётся закрытым. Второй вызов с уже стоящим флагом пункт снова не открывает.

Тест без базы: `test/kremlin-route.test.js`, «financeTextReopen открывает need-finance без текстового ответа один раз».

Тот же флаг после рестарта Postgres уже проверяет `test/store.test.js`, «financeTextReopen один раз и не повторяется после рестарта». В CI он идёт, когда задан `DATABASE_URL`.
